# Spec: v0.3a 生成历史记录

## 1. 背景与目标

v0.2 完成了换装生成的核心流程，但每次刷新页面或重新生成后，之前的结果就丢失了，用户无法回看。v0.3a 目标是在客户端本地持久化生成历史，让用户可以在同一浏览器中随时回顾历史结果，无需重新生成。

## 2. 用户故事 / 使用场景

- **回看历史**：用户生成了几次效果，想对比第一次和第三次的结果，点击历史缩略图即可切换查看
- **清理历史**：用户不想保留某次效果，点击删除按钮移除该条记录
- **历史上限**：用户生成超过 10 次后，最旧的记录自动被新记录替换，不需要手动管理

## 3. 功能需求 (FR)

| 编号 | 需求 | 验证方式 |
|------|------|---------|
| FR-001 | 每次换装生成成功（resultImage 有值）后，将结果图与时间戳作为一条记录写入 localStorage | 生成成功后打开 DevTools → Application → localStorage，确认新条目存在 |
| FR-002 | 历史记录存储结构包含：唯一 id、时间戳、结果图（缩略图 base64）；缩略图通过 Canvas 将原结果图等比缩小至宽度不超过 120px，以减小存储体积 | localStorage 中每条记录大小可接受（< 30KB） |
| FR-003 | localStorage 中历史记录上限为 10 条；写入新记录时若已有 10 条，自动删除最旧的一条（按时间戳排序） | 生成第 11 次后，localStorage 中仍只有 10 条，且最旧的已消失 |
| FR-004 | 结果区下方渲染横向可滚动的历史缩略图列表，每条显示缩略图与相对时间（如"3 分钟前"） | 有历史记录时列表可见；无历史时列表区域不显示 |
| FR-005 | 点击历史缩略图，将对应的结果图（原始尺寸 base64）设为当前展示的 resultImage | 点击历史条目后，结果展示区切换为该次结果图 |
| FR-006 | 每条历史记录提供删除按钮，点击后从 localStorage 删除该条记录并从列表移除 | 删除后列表实时更新，刷新页面后该条记录也不再出现 |

## 4. 成功标准 (SC)

| 编号 | 标准 |
|------|------|
| SC-001 | 生成成功后，历史列表自动新增一条缩略图，无需手动操作 |
| SC-002 | 刷新页面后历史记录依然存在，点击可正常切换展示 |
| SC-003 | 历史记录达到 10 条后再生成，最旧的一条自动消失，总数保持 10 |
| SC-004 | 删除某条记录后，列表实时更新，刷新页面后确认已消失 |
| SC-005 | localStorage 写入失败时（如存储空间已满），页面不崩溃，静默跳过存储，正常展示结果 |

## 5. 范围与边界

**In Scope**
- 客户端 localStorage 读写逻辑（存储、读取、淘汰、删除）
- 缩略图生成（Canvas 等比缩小至 120px 宽）
- 历史列表 UI 组件（横向滚动、缩略图、时间、删除按钮）
- 点击历史条目切换 resultImage 的状态联动

**Out of Scope**
- 云端历史同步（无用户系统）
- 存储人像图或服装图（只存结果图）
- 历史记录导出
- 跨设备历史共享
- 多浏览器 / 隐私模式持久化（这是 localStorage 的固有限制，不做额外处理）

## 6. 依赖与约束

- 依赖浏览器原生 API：`localStorage`、`Canvas 2D Context`
- 结果图（resultImage）由 `page.tsx` 以 base64 字符串形式持有；历史模块从 `page.tsx` 接收 resultImage 触发写入
- 历史列表组件建议新建 `components/HistoryBar.tsx`，由 `page.tsx` 管理状态并传入 `onSelect` 回调
- localStorage key 统一为 `tryon_history`，value 为 JSON 数组
- 存储写入需包裹 try/catch，防止 QuotaExceededError 导致页面崩溃
