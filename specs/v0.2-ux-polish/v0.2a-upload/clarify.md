## 2. 技术选型澄清

### Q1. 粘贴监听范围：上传区聚焦 vs. 全局

- **位置**：spec.md FR-001 / 第 3 节
- **问题**：当前实现中，`onPaste` 事件绑定在上传区 div 上，仅在该区域聚焦时响应粘贴。用户若在页面其他地方粘贴（如刚打开页面未点击任何地方）不会触发。Brief 写「Ctrl+V / 截图直接粘贴」，是否隐含全局粘贴？
- **可选方案**：
  - A) 维持现状：仅上传区聚焦时响应（当前实现）
  - B) 监听 `document` 级别的 `paste` 事件，全局响应
- **建议**：A。全局监听容易干扰其他输入框（如将来添加文本输入），且用户心智模型是"粘贴到上传区"。
- **答复**：A — 仅上传区聚焦时响应粘贴

### Q2. 压缩输出格式：强制 JPEG vs. 保留原始格式

- **位置**：spec.md FR-002 / `compressImage()` 实现
- **问题**：当前压缩函数对所有超过 1200px 的图片统一输出 JPEG（quality 0.85），即使原始格式是 PNG（可能带透明通道）。压缩后透明背景会变黑/白。对换装场景（人物照），这通常没问题；但若用户上传带透明背景的服装图，可能影响效果。
- **可选方案**：
  - A) 维持现状：统一输出 JPEG（当前实现）
  - B) PNG 输入保持 PNG 输出，仅 JPEG/WEBP 输入输出 JPEG
- **建议**：A。换装场景上传的照片几乎都是不透明的，JPEG 压缩率更优。可在 spec 中显式标注此取舍。
- **答复**：A — 统一输出 JPEG，接受透明通道丢失的取舍

### Q3. 压缩 quality 参数是否需要可配置

- **位置**：spec.md FR-002
- **问题**：压缩质量硬编码为 0.85。是否需要将此值作为可调参数（如通过 props 或环境变量）？
- **可选方案**：
  - A) 保持硬编码 0.85（当前实现）
  - B) 通过 `UploadZone` props 暴露 `compressionQuality?: number`
- **建议**：A。v0.2 不需要为调参做准备，过早抽象。
- **答复**：A — 保持硬编码 0.85

## 3. 数据模型 / 接口契约澄清

### Q4. 压缩后 File 的文件名规则

- **位置**：spec.md FR-002 / `compressImage()` 第 40-43 行
- **问题**：当前实现将文件名后缀替换为 `.jpg`（`file.name.replace(/\.\w+$/, ".jpg")`）。若原文件名无扩展名（如截图粘贴生成的 File 名为 `image.png` 或空），行为是否符合预期？粘贴产生的 File 的 `name` 字段由浏览器决定，可能为空字符串。
- **可选方案**：
  - A) 维持现状，依赖浏览器给出的 name（当前实现）
  - B) 压缩后统一命名为 `compressed_${Date.now()}.jpg`
- **建议**：A。文件名仅在 `File` 对象内部存在，最终传给 API 的是 base64，文件名不影响功能。
- **答复**：A — 依赖浏览器给出的 name，不做额外处理
