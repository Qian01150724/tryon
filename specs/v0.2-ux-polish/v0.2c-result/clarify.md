## 2. 技术选型澄清

### Q1. 滑动条实现方式：透明 range input vs. 鼠标事件监听

- **位置**：spec.md FR-001 / §6 依赖与约束
- **问题**：当前实现用透明 `<input type="range">` 覆盖在图片上，原生处理拖拽和触摸。替代方案是手写 `onMouseMove` + `onTouchMove`，可获得更精细的视觉控制（如自定义手柄样式），但代码量更大。
- **可选方案**：
  - A) 维持现状：透明 range input（当前实现，简单可靠）
  - B) 手写鼠标/触摸事件，自定义手柄
- **建议**：A。range input 原生支持键盘操作和移动端触摸，无需额外处理。
- **答复**：A — 维持现状

### Q2. 放大弹窗仅展示结果图 vs. 支持在弹窗内也对比

- **位置**：spec.md FR-002
- **问题**：当前放大弹窗只展示换装结果图，不包含对比滑条。用户若想在全屏状态下对比，需要关闭弹窗回到对比视图。
- **可选方案**：
  - A) 维持现状：弹窗仅展示结果图（当前实现）
  - B) 弹窗内也加对比滑条
- **建议**：A。弹窗主要用于查看细节，全屏对比复杂度高，v0.2 不做。
- **答复**：A — 维持现状

## 3. 数据模型 / 接口契约澄清

### Q3. sliderPos 初始值和重置时机

- **位置**：spec.md FR-001 / SC-001
- **问题**：`sliderPos` 初始值为 50（居中）。用户换装后重新生成，`sliderPos` 是否重置回 50？当前代码中 `sliderPos` 为组件 state，重新渲染（resultImage 变化）不会自动重置，上次拖动的位置会保留。
- **可选方案**：
  - A) 维持现状：保留上次拖动位置（当前实现）
  - B) 每次 resultImage 变化时重置为 50
- **建议**：A。换装后保留滑条位置，用户可在同一位置对比新旧结果，体验更连贯。
- **答复**：A — 维持现状
