# 功能规格合集

> 所有版本的功能规格按版本顺序汇总。每轮 `/finish` 后追加新版本章节。
> 项目原则约束：见 `docs/intent.md`（隐私、极简、无需登录、不做社交/视频/3D）。

## v0.1 — 核心交互闭环

> **本版变更**：从零建立，无上一版基线。
> 新增：双栏上传区、生成按钮、基础结果展示、mock API 路由。
> 上一版基线：无

无独立 spec 文件，核心设计见 `docs/intent.md`。

**已落地功能**：
- 双栏上传区（点击 / 拖拽），支持 JPG、PNG、WEBP
- 生成按钮（禁用 → 可用 → 生成中 → 完成）
- 基础结果展示（单图）
- 基础 loading（旋转圈）
- `/api/tryon` mock 路由，延迟返回示例图

## v0.2a — 上传体验优化

> **本版变更**：在 v0.1 基础上新增上传区的粘贴、压缩、键盘操作、内联错误。
> 改动文件：`components/UploadZone.tsx`（单文件）。
> 上一版基线：v0.1

**背景**：v0.1 上传区只支持点击和拖拽，缺少粘贴、大图压缩、键盘可访问性和内联错误提示。

### 功能需求（FR）

| 编号 | 需求 | 验证方式 |
|------|------|---------|
| FR-001 | 上传区监听 `onPaste`，从 ClipboardData 提取 image/* 类型文件触发上传 | Ctrl+V 粘贴截图后显示预览 |
| FR-002 | 上传前检测宽或高 > 1200px；超过则 Canvas 等比缩放，JPEG 0.85 输出新 File | 上传 2000px 图片，API 收到的 base64 对应尺寸 ≤ 1200px |
| FR-003 | 格式（非 image/*）或大小（> 10MB）校验失败时，上传区下方显示内联错误文本，不调用 `window.alert` | 拖入 .pdf 后显示红色文字，无弹窗 |
| FR-004 | 容器 `tabIndex={0}`，`onKeyDown` 捕获 Enter/Space 触发文件选择；聚焦时显示 focus ring | Tab 聚焦后按 Enter 弹出文件选择器 |

### 成功标准（SC）

| 编号 | 标准 |
|------|------|
| SC-001 | 粘贴截图后显示预览，与点击上传结果一致 |
| SC-002 | `compressImage()` 返回的 File 对应图片宽高均 ≤ 1200px |
| SC-003 | 上传非图片或超大文件，无 `alert()`，上传区下方出现红色错误文本 |
| SC-004 | 纯键盘可完成上传：Tab 聚焦 → Enter 打开选择器 → 选文件 → 预览显示 |
| SC-005 | 上传成功后错误文本自动清除 |

## v0.2b — 等待体验优化

> **本版变更**：在 v0.2a 基础上新增等待中的进度感知与取消/超时控制。
> 改动文件：`components/ResultDisplay.tsx`（EXPECTED_MS + 进度数字）；`GenerateButton.tsx`、`page.tsx` 为 v0.1 已有功能的文档补齐，无代码改动。
> 上一版基线：v0.2a

**背景**：v0.1 等待状态只有旋转圈，用户无法感知进度，无法主动取消，超时也没有提示。

### 功能需求（FR）

| 编号 | 需求 | 验证方式 |
|------|------|---------|
| FR-001 | 生成中展示 5 条动态提示语，每 2 秒切换，循环 | 点击生成后每 2 秒文字更新 |
| FR-002 | 进度条 ease-out 曲线增长，最高 90%，不跳到 100%；右侧显示数字百分比 | 等待过程进度条持续增长，始终 ≤ 90% |
| FR-003 | 生成中显示"取消"按钮，点击通过 AbortController 中止请求，页面回 idle | 点取消后加载状态消失，上传区和按钮恢复 |
| FR-004 | 请求超过 30 秒自动 abort，显示"生成超时（超过 30 秒），请重试" | 模拟延迟 > 30 秒，出现超时提示 |

### 成功标准（SC）

| 编号 | 标准 |
|------|------|
| SC-001 | 生成期间文字每 2 秒切换，5 条依次循环 |
| SC-002 | 进度条整个等待过程始终 ≤ 90%，不跳 100% |
| SC-003 | 点取消后 stage 变 `"idle"`，error 清除，加载圈和取消按钮消失 |
| SC-004 | 30 秒后 error 文本为"生成超时（超过 30 秒），请重试" |
| SC-005 | 生成完成或失败后，两个定时器均清除，无内存泄漏 |

## v0.2c — 结果体验优化

> **本版变更**：在 v0.2b 基础上新增前后对比滑动条和全屏放大弹窗。
> 改动文件：`components/ResultDisplay.tsx`（有结果分支，v0.1 已实现，本轮为文档补齐，无代码改动）。
> 上一版基线：v0.2b

**背景**：v0.1 结果展示只有静态单图，无对比和放大能力。

### 功能需求（FR）

| 编号 | 需求 | 验证方式 |
|------|------|---------|
| FR-001 | 有结果图且有原图时，显示前后对比滑动条：结果图为底层，原图为上层裁切，拖手柄控制分割线 | 拖动滑条，原图和结果图随手柄位置切换显示比例 |
| FR-002 | 对比区右下角有放大按钮，点击弹全屏弹窗展示结果图，点遮罩或 ✕ 关闭 | 点放大后出现全屏弹窗，点 ✕ 或遮罩后消失 |

### 成功标准（SC）

| 编号 | 标准 |
|------|------|
| SC-001 | 滑条初始 50%，拖动后按比例显示，无撕裂或错位 |
| SC-002 | 对比区有"原图"和"换装后"标签，分别标注左右两侧 |
| SC-003 | 放大弹窗背景深色遮罩（≥ 80% 不透明），结果图居中，不超出屏幕 |
| SC-004 | 无原图时结果图直接展示，不显示滑动条，点击图片触发放大 |
| SC-005 | `isZoomed` 在弹窗关闭后重置为 false，可再次放大 |

## v0.3a — 客户端历史记录

> **本版变更**：在 v0.2c 基础上新增客户端生成历史功能（FR-001~FR-006 全部为新增）。
> 新增文件：`lib/history.ts`、`components/HistoryPanel.tsx`。
> 改动文件：`components/ResultDisplay.tsx`（底部按钮替换 + 6 个新 props）、`app/page.tsx`（3 个新 state + 3 个新回调）。
> 上一版基线：v0.2c

**背景**：每次刷新或重新生成后，之前结果丢失，用户无法回看。目标是在客户端本地持久化生成历史。

### 功能需求（FR）

| 编号 | 需求 | 验证方式 |
|------|------|---------|
| FR-001 | 每次换装生成成功后，将结果图与时间戳写入 localStorage | 生成成功后 DevTools → localStorage，确认新条目存在 |
| FR-002 | 存储结构：`{ id, timestamp, thumbnail }`；缩略图 Canvas 等比缩至 120px 宽，JPEG 0.85 | localStorage 每条记录 < 30KB |
| FR-003 | 上限 10 条；超出时自动删除最旧一条 | 生成第 11 次后 localStorage 仍只有 10 条 |
| FR-004 | 结果卡底部"历史记录"按钮，点击展开/收起横向可滚动缩略图面板；无历史时禁用 | 有历史时按钮可点击，面板展开；无历史时灰色禁用 |
| FR-005 | 点击历史缩略图，将对应缩略图 base64 设为当前 resultImage | 点击后结果展示区切换为对应图 |
| FR-006 | 每条历史记录提供删除按钮，点击后从 localStorage 删除并从列表移除 | 删除后列表实时更新，刷新后该条不再出现 |

### 成功标准（SC）

| 编号 | 标准 |
|------|------|
| SC-001 | 生成成功后，历史列表自动新增一条缩略图，无需手动操作 |
| SC-002 | 刷新页面后历史记录依然存在，点击可正常切换展示 |
| SC-003 | 历史达到 10 条后再生成，最旧一条自动消失，总数保持 10 |
| SC-004 | 删除某条后，列表实时更新，刷新后确认已消失 |
| SC-005 | localStorage 写入失败时，页面不崩溃，静默跳过 |

### 关键设计决策

- FR-004 实际落地为"点击按钮展开/收起面板"，非 spec 原文"常驻列表"（design 阶段决策）
- FR-005 切换历史时使用缩略图（120px），不存原始大图（clarify Q4 选 B）
- 相对时间每分钟 setInterval 刷新（clarify Q2 选 B）

### 已知遗留

- 切换历史后放大弹窗显示低清缩略图（已接受，如需改善下一轮加 600px 中等尺寸字段）
- 相对时间刷新精度最多差 60 秒（可接受）
